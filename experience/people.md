# 用人

## 按任务性格配人，不是按"谁有空"

同一件活给错人，你会得出"他不行"的错误结论。**先看任务性格，再看谁闲着。**

| 任务性格 | 配谁 | 为什么 |
|---|---|---|
| 长链条审计、细致算术、要按规格做 | **偏长偏慢、动手前先算账的人** | 他的"慢"在这里是**深度**；催他等于让他交半份审计 |
| 快速试错、参数扫描、要敢猜敢改口 | **先跑再报的人** | 他会给你**一张表**，而不是**一个结论** |
| 前沿功能设计、目标本身该不该存在 | **顾问** | 这类问题只有高阶判断能回答，程序细节别拿去浪费 |
| 只读测量、对照读数 | **最闲的人** | 最便宜的高价值产出：一次只读对照常常比一次实现更值钱 |

**我犯过的错**：把三件长链条审计连续派给同一个人，然后觉得他"慢"。
**那是我的调度问题**——他的任务性格全是慢活。后来我把快节奏的活给了另一个人，
两条线都快了。

## 顾问怎么用

1. **只问只有他能回答的**。技术口味问技术顾问；"这个功能该不该存在"问产品顾问。
   我把一段"某处该用哪种错误类型"的程序细节拿去问了最贵的产品顾问，
   用户的评价是"拿这些细节问 sota 模型还是太浪费了"。
2. **要判据，不要结论**——尤其你要做的是**审美/方向**判断时。
   我在出图**之前**先问"一张图上的什么特征算'读起来像被水塑造过'，按重要性排序"，
   拿到的是一套**可以复用的语言**（`拓扑占判断的 60%`、`哪三条穿帮`），
   于是后面每一轮图都有同一把尺。
3. **顾问说"目标该改"时，认真对待它。** 有一次顾问指出：这套物理**结构上给不出**
   我们最初想要的那种效果（它属于另一个"语域"），并给了**该改成什么**。
   照做的收益不是"少走弯路"，而是**未来的窗口不会去追一个给不出的东西**。
   这一条我写进了工程文档，因为它是**目标级**的更正。
4. **顾问也会被"预判"骗**。顾问会替你预判失败模式（"侵蚀那一侧必然更平，
   而'平'读起来就是更没意思——这是与你要判的东西无关的混淆项"），
   并给出**两遍判法**。**照它说的先承诺，再看图**——否则你会在看到图之后
   临时改判据，那就等于没有判据。

## 让组员顶回来

**一个只会照做的队伍，会把你的每一个错误执行到底。**

我这轮的实际情况是：**被组员纠正的次数远多于我纠正他们**。四次说错文件面、
一次"你这条指示会踩回一个刚记档的缺陷"、一次"你要的 6 本其实是 5 本"、
一次"这条判据的 oracle 已经和新求解器不是同一套物理"。

所以：

- 派活时**主动说"我可能记错，先核对再动手"**——最便宜的保险；
- 组员说"我不确定，请你裁"时，**别回"你看着办"**——他在把不确定性交给你，那是信息；
- 组员说"你这条做不到"时，**先假设他是对的**，让他给理由再判；
- 组员**主动报自己的失误**（"我删过自己的缓存目录""我的判据第一版是假绿的"）时，
  **认下来、记下来、不要让他觉得多事**。这类自报比任何交付都值钱。

## 走人之前必须留下的四样

知识不在文档里，在人头上。有人要走（额度用完、或者你换人）之前：

1. **在途的活**：他手上有几件、到哪一步、有没有未提交的东西。**半途换手最贵**——
   优先让他交完。
2. **他踩过的坑**：这个项目/这套工具**会骗人的地方**。这些不是常识，
   新人一定会重犯，而且**没有文档就永远不会被记下来**。
3. **他做过但你还没记档的判断**：他拍过的板、他为什么那么拍。
4. **他手上"悬着的口惠"**：他说过"以后可以补一列/可以再做一次对照"的那类。
   他自己会主动提（好的组员会），**你要接住**——那往往正是你下一步需要的输入。

## 工作空间的生命周期：要机械化，不要靠记

**症状**：给每个任务开一个独立工作目录（每个目录带自己的一份构建产物），
任务做完没人回收。我让这件事积累到 **16 个工作目录、吃掉几十 GB**，
直到磁盘满掉。

**规矩**：
- **一个人同时最多一个工作目录**；交付被合入后，**由组长回收**，不要让组员自己删；
- **一条线换方向就先把旧目录交回来**——**分支名是存档，构建产物不是**；
- 回收必须**机械化**（一个只读报告 + 一个显式回收开关），而且**脏的、未合并的永不回收**
  （那是别人未提交的活），游离状态的只在**点名**时才收（它没有分支名记录自己是什么）；
- ⚠ **回收会伤到还坐在里面的别人**：他的 shell 落在一个已删除的目录上之后，
  git 会**从缺失的目录往上走到主仓库**，于是他下一步命令**静默打在主干上**。
  我因此让一位组员的 rebase 跑在了主检出上。⇒ **回收时明确广播"谁还在里面"**，
  并且**回收别人留给下一步用的目录之前先问一句**。

## 别让一个人变成单点

如果一件事只有一个人会做，那么他走的那一刻，你失去的不是一份工时，而是**这件事的能力**。
所以要**尽量把"怎么验证"写成所有人能读的东西**（判据、读数口径、复现命令），
而不是留在某个人的手感里。这也是为什么"回报里必须有哪几样"值得写进每一份工单。
